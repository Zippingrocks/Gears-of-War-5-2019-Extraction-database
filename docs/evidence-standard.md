# Evidence Standard

Every durable conclusion is represented as a claim under `evidence/claims/`.

## Required fields

- `state`: hypothesis, observed, decoded, validated, rejected, or unknown.
- `confidence`: low, medium, or high.
- `scope`: exact game, platform/build, and optional root, maps, packages, or objects.
- `claim`: one falsifiable statement.
- `evidence`: repository-local proof references or stable public specifications.
- `limitations`: what the evidence does not prove.

## Native proof hierarchy

1. Repeated byte-level structure with recorded offsets and independent fixtures.
2. Parsed native metadata with stable object and dependency identity.
3. Runtime or tool agreement against the same build.
4. Numerical transform and coverage audits.
5. Visual agreement in Blender.

Visual agreement is useful corroboration but never the sole proof of field semantics, placement ownership, or map completeness.
